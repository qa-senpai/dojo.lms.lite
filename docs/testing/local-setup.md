# Як запустити Dojo LMS Lite і виконати перший автотест

Спочатку ви запустите LMS на своєму комп’ютері, увійдете як студент і перевірите в базі даних, що запис на курс зберігся. Потім запустите той самий застосунок у тестовому середовищі Playwright.

## 1. Підготуйте комп’ютер

- **Node.js 22.x версії 22.17.0 або новішої в цій гілці** та **npm**. npm входить до стандартного інсталятора Node.js. Проєкт використовує вбудований модуль `node:sqlite`.
- **Git**, якщо отримуєте код через клонування. Якщо викладач дав ZIP-архів, достатньо його розпакувати.
- **Браузер** для роботи з LMS і **термінал** для команд. На Windows використовуйте PowerShell, на macOS чи Linux — Terminal. Для написання власних тестів знадобиться редактор коду.

Відкрийте новий термінал після встановлення й перевірте версії.

```sh
node --version
npm --version
git --version
```

Перша команда має вивести, наприклад, `v22.17.1`, решта — номери версій відповідних програм. Якщо працюєте з архівом, перевірку Git можна пропустити.

## 2. Відкрийте каталог проєкту

Якщо отримали посилання на Git-репозиторій, замініть `URL_ВІД_ВИКЛАДАЧА` адресою для клонування й виконайте команду.

```sh
git clone URL_ВІД_ВИКЛАДАЧА
```

У клонованому або розпакованому каталозі знайдіть папку LMS, де поруч лежать `package.json`, `package-lock.json` і `.env.example`. Відкрийте термінал саме в ній. Перевірте, що працюєте з потрібним застосунком.

```sh
npm pkg get name
```

Очікуваний результат — `"dojo.lms.lite"`. Усі подальші команди запускайте із цієї папки.

## 3. Налаштуйте середовище й установіть залежності

Перед першим запуском скопіюйте шаблон налаштувань. Якщо вже маєте власний файл `.env`, збережіть його й перевірте значення в ньому.

**macOS або Linux**

```sh
cp .env.example .env
```

**Windows PowerShell**

```powershell
Copy-Item .env.example .env
```

Для цього гайда залиште стандартні значення.

| Налаштування в `.env`              | Для чого потрібне                                                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `APP_URL=http://localhost:3000`    | Адреса, за якою ви відкриватимете LMS у браузері. Сервер звіряє з нею джерело запитів під час надсилання форм. |
| `DATABASE_PATH=./data/dojo.sqlite` | Шлях від каталогу проєкту до файлу локальної бази.                                                             |
| `SEED_ADMIN_*` і `SEED_STUDENT_*`  | Email і пароль для створення двох навчальних акаунтів.                                                         |

Завантажте залежності версій, зафіксованих у `package-lock.json`. Для цього потрібен інтернет.

```sh
npm ci
```

## 4. Створіть базу й запустіть LMS

```sh
npm run db:seed
```

Команда створює каталог `data`, файл SQLite, таблиці, два акаунти та курс **«Перші кроки в автоматизації»**. Ознака успіху в терміналі — `Demo course ready`. Команду можна повторити. Вона зберігає паролі наявних акаунтів і зміни в наявному демонстраційному курсі.

```sh
npm run dev
```

Залиште цей термінал відкритим. Перейдіть на [локальну LMS](http://localhost:3000). Має відкритися каталог із демонстраційним курсом. Для швидкої перевірки сервера відкрийте [сторінку стану API](http://localhost:3000/api/health). Очікувана відповідь — `{"status":"ok"}`.

Відкрийте [сторінку входу](http://localhost:3000/sign-in). Для стандартного `.env` діють такі навчальні акаунти.

| Роль          | Email               | Пароль               |
| ------------- | ------------------- | -------------------- |
| Студент       | `student@dojo.test` | `Student-demo-2026!` |
| Адміністратор | `admin@dojo.test`   | `Admin-demo-2026!`   |

Увійдіть як **студент**, відкрийте демонстраційний курс і натисніть **«Записатися на курс»**. Відкрийте [кабінет студента](http://localhost:3000/dashboard) і переконайтеся, що курс з’явився у вашому навчанні. На наступному кроці ви знайдете цей запис у SQLite.

## 5. Під’єднайтеся до SQLite й перевірте результат

SQLite зберігає дані у файлі. Для під’єднання достатньо шляху до нього та прав на читання. Логін і пароль із попереднього кроку потрібні лише для входу в LMS.

**Через графічний клієнт.** Якщо зручніше переглядати таблиці у вікні, відкрийте **DB Browser for SQLite**, натисніть **Open Database** і виберіть наявний файл `data/dojo.sqlite` з каталогу LMS. На вкладці **Browse Data** виберіть `enrollments`, щоб побачити пари `user_id` та `course_id`. На вкладці **Execute SQL** виконайте запит, щоб прочитати їх як email та назви курсів.

```sql
SELECT u.email, c.title
FROM enrollments AS e
JOIN users AS u ON u.id = e.user_id
JOIN courses AS c ON c.id = e.course_id;
```

## 6. Запустіть перший тест Playwright

У терміналі з dev-сервером натисніть **Ctrl+C**. Встановіть Chromium для версії Playwright із проєкту та зберіть застосунок.

```sh
npx playwright install chromium
npm run build
```

На Ubuntu, якщо Playwright повідомляє про відсутні системні бібліотеки, виконайте `npx playwright install --with-deps chromium`. Після успішної збірки запустіть один готовий сценарій у видимому вікні браузера.

```sh
npm run test:e2e -- tests/e2e/lms.spec.ts -g "invalid login" --headed
```

## Якщо щось пішло не так

| Симптом                                                                           | Як виправити                                                                                                                        |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| npm повідомляє, що не знаходить `package.json`                                    | Перейдіть у папку LMS і повторіть перевірку з кроку 2.                                                                              |
| Node.js не знаходить `node:sqlite`                                                | Перевірте `node --version` у поточному терміналі та перейдіть на Node.js 22.x від 22.17.0.                                          |
| Каталог порожній або SQLite-клієнт не бачить таблиць                              | Звірте шлях до відкритого файлу з `DATABASE_PATH`, виконайте `npm run db:seed` у папці LMS і повторно відкрийте файл.               |
| Порт 3000 зайнятий або форми повертають помилку Origin                            | Для порту 3001 задайте `APP_URL=http://localhost:3001` у `.env`, запустіть `npm run dev -- --port 3001` і відкрийте саме цю адресу. |
| Playwright не знаходить `.next/standalone/server.js` чи виконуваний файл браузера | Для відсутнього сервера виконайте `npm run build`, для браузера — `npx playwright install chromium`.                                |
| Playwright повідомляє, що порт 3106 зайнятий                                      | Завершіть попередній тестовий запуск, який використовує цей порт, і повторіть тест.                                                 |

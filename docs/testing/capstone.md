# Ідеї для випускного проєкту

Тестуйте через UI та HTTP API; працюйте лише з власним локальним стендом
або виділеним викладачем сервером. Кожен тест створює власні дані та прибирає
їх.

1. Реєстрація: валідні дані, дублікат email, неправильний email, короткий пароль.
2. Вхід: успіх/помилка, збереження сесії після reload, logout, захист dashboard.
3. Ролі: студент не бачить адмінку й отримує 403 на admin mutations.
4. Курси: CRUD, чернетка/публікація, пошук/категорія, empty state.
5. Розділи: CRUD, зміна порядку, невидимість чернеток, навігація вперед/назад.
6. Доступ: запис, ручне додавання, відкликання, закритий вміст і файли.
7. Quiz: неправильна/правильна відповідь, повторна спроба, збереження результату.
8. JavaScript: correct solution, wrong answer, syntax error, нескінченний цикл.
9. ДЗ: submit → revision → resubmit → accept; коментар та прогрес.
10. Completion: лише прочитання не завершує курс з невиконаними вправами/ДЗ.
11. Файли: upload/download, content verification, extension/size validation.
12. API: відсутня сесія, CSRF Origin, чужий course/chapter ID, malformed JSON.
13. UI: мобільний viewport, клавіатура, labels/roles, пусті списки, помилки мережі.

Для локальних тестів використовуйте окремий DATABASE_PATH; Playwright runner стенда
сам створює й видаляє throwaway DB. Seed і admin CRUD достатні для fixtures.
